# 图画法 cookbook

什么时候画图、画什么、怎么画才不翻车。全部用 `design-system.md` 的原语。

## 什么时候画图

**唯一标准:内容里存在真实的二维关系。** 组成/边界、流向/推进、对比/分布、证据/支撑——这些是空间关系,画图;清单、定义、字段、注意事项——这些不是,老实写表格或散文。一条经验:**如果图里只有 2 个框 1 根箭头,它就不该是一张图**——写一句话。

## 选型速查

| 内容形状 | 画法 |
| --- | --- |
| 中心系统 + 外部消费方/依赖 + 内部职责带 | 边界图:`mv-region`(中心,tone-accent)+ 外部 region(is-external)+ 内部 band 网格 |
| 上下/从属坐标("X 是 Y 之下的运行时") | 分层坐标图:region 纵排 + 双向语义合成一根带 ↓↑ 标签的连线 |
| 对象及其关系(ER 式) | 对象图:节点摆网格位,typed 连线 |
| 状态推进 / 阶段链 | `.mv-chain`(≤6 步)或 diagram + 连线(长链/有分支) |
| 阶段 + 扇出扇入 | diagram:主轴链 + runner 列 + 每组 3 根连线 |
| 双场景/双回路互相成就 | 三角环图:3 节点 3 连线成环 |
| 选项 × 维度 | **不要画**,用 `.mv-table`;超过 6 个选项转置 |
| 清单/规则/字段 | **不要画**,`.mv-facts` 或表格 |

## 画法要点

### 布局

- 图容器是 CSS grid/flex 的自由画布:在 `<style>` 里用 `#视图id` 前缀定义网格(`grid-template-columns/areas`),节点直接摆进格子。容器查询 `@container(max-width:...)` 做窄宽降级。
- **fan-out/fan-in 图必须占满整行宽度**,不要塞进 cols-2 网格的半宽格子——容器查询会把主轴压成纵列,fan 形态消失。
- 中心系统占主面积;外部对象虚线 region 退居上/右/下;每个可见边框都要能回答"它圈住了什么"(无语义的布局包装不要画框)。

### 连线(运行时绘制)

- 声明 `<i class="mv-edge" data-from="a" data-to="b" data-label="..." data-kind="calls">`,运行时按真实 DOM 位置路由、避障、放标签。`data-route="v"` 强制纵向。
- **同两点间的往返两根线会完全重叠**:合成一根,标签写双向语义(`↓ 入口 · ↑ 归集`)。
- 连线端点可以是任何带 `data-node` 的元素(节点、band、region),不只 `.mv-node`。
- 连线是稀缺资源:架构图里 2-4 根讲清主关系就够;结构关系(包含/分层)让**嵌套和位置**表达,不要画箭头。层带纵排本身就是"分层"。
- 标签被自动抑制(放不下时)是常态,别堆长标签;长语义挪进图注。

### 密度与节奏

- 一屏信息密度优先给"结构":层带、边界、主链;解释性长句放图下的卡片/事实行。
- 高亮只有一处重点(`.is-primary` 给主对象/主路径),处处高亮等于没有高亮。
- 图注(`.mv-diagram-cap`)写"看图说话"补不了的东西:例外、口径、来源说明。

## 实战踩过的坑(反例)

1. **给 7 步管线用 `.mv-chain` 不加 `.no-grow`**:折行后最后一个节点被拉成全宽孤卡。
2. **把"事件流"连线从执行层拉到观测层**:穿过中间的知识层带——band 不是避障障碍物,跨带长连线必然穿层。要么不连(带内自说明),要么改结构。
3. **在标题/caption 里写"§1.1"却不引用含该编号的块**:数字门会拒。标题块由"复述了标题文字的 h2/h3"认领。
4. **手写 "VIEW 01" 编号**:编造数字,过不了数字门;用 `<span class="vn"></span>` 计数器。
5. **把源文没有的形容词画进去**("观测横切全栈"——源文没提横切):词锚防换词防不了添加,每个关系断言先问"源文说了吗"。
6. **region 套 region 三层框**:布局包装不画框,显著嵌套边界不超过两层。
